# Changelog

## 1.7.12 — a safe release (1.7.11 + bounded fixes only)

1.7.12 is 1.7.11 with only the fixes below. Every text heuristic — test-file recognition, one-line tests, claim parsing, request and intent detection, pulled files, the pre-tool hook's shell forms, hook-drift checks — is exactly as in 1.7.11. The larger 1.7.12 effort on those heuristics kept producing regressions (a verdict of DONE where 1.7.11 said NOT DONE), so it is deferred; it lives on the branch `wip/1.7.12-heuristics`. The promise of this release: wherever 1.7.11 said NOT DONE, 1.7.12 says NOT DONE too (or NOT JUDGED, when there is no license).

**The package customers install behaves as the source (1a).** The build no longer lets the obfuscator change what the code does: an object literal beside `&&` / `||` / `??` is kept from being evaluated before the operator decides (`c && { callee: c[1] }` threw in the built product), a spread call through a bare name keeps all its arguments, `transformObjectKeys` is off (it read a guarded object's keys on the path the condition skipped), and every file is checked before it is obfuscated — a regex that changes when rebuilt from its string, or a shape the obfuscator would change, stops the build with the file and line. Flattening runs on every function, so the suite against `dist/` meets every transform in every build, and a failing check is named in the build's output. The verdict no longer reads the police's own files (the vendored copy) as the agent's work, so the source and the encrypted package judge the same work the same way. `node scripts/build-dist.mjs` exits 0: the full suite passes on the built package.

**An ended trial passes nothing unjudged (1b).** After the 2-day trial with no license, `check` (and `prove`, `gates`, `selftest`, `repeat`, `run`, `attest sign` / `verify`, `shield audit`) prints NOT JUDGED and exits 3 — never DONE; `--out` says NOT JUDGED; the GitHub Action maps exit 3 to a failed step with the verdict `NOT JUDGED`. The agent's hooks (Claude Code, Cursor, Codex, Copilot) and the git hooks never block, and say plainly that the police is not checking and how to license — in the project's language (`--lang`, `POLICE_LANG`, or harness.json `"lang"`). The trial's two records are sealed with this machine's key: while a sealed copy is there, a record written by anything else is not believed; a record with no seal at all (1.7.11 wrote them so) is read as 1.7.11 read it when no sealed copy is left, so an upgrade, or a run of a 1.7.11 copy on the same machine, keeps the trial's clock and never starts a new trial. The pre-tool hook refuses the agent's writes and removals of the trial records and the license file: Write / Edit wherever the license is kept, and the plain shell forms (`rm`, `mv`, `cp`, a redirect …) on the trial records and on a license in its default place (`~/.agent-police/license.json`) — a license kept at `AGENT_POLICE_LICENSE=<path>` is guarded against Write / Edit only, as in 1.7.11. The README says all of this.

**No hint names a package that is not ours (1c).** No message, default or README line tells anyone to run `npx agent-police` (the name is not on npm) or to install `agentproof` from npm (someone else's package). Hints name the command that exists for the install: the vendored copy (`node .agent-police/bin/agent-police.mjs …`), the package in `node_modules` by its path, or the copy the install used by its absolute path; an install run from npx's cache vendors itself. A suite check reads every shipped file and message for it. Only hints changed: the pre-tool hook's read-only commands while `"ask": "first"` waits for answers are 1.7.11's, `npx agent-police check` / `task status` among them — a 1.7.11 install wrote that line into the committed instructions, and an upgrade that does not re-run install must not block the agent for following it. The hub page's copied commands (`hub order` among them, where the owner types the key's passphrase) name one of two fixed forms — the vendored copy or `node_modules` — never a path taken from a project's summary, which anyone who can write a summary would choose.

**CI judges only with the base branch's harness.json (4a).** In the GitHub Action, `check --base` and the workflow `agent-police ci` writes, a pull request into a base branch with no committed `harness.json` is NOT DONE, with a plain message (commit `harness.json` to the base branch first) — never judged by its own copy, never the base's tree judged in its name. In the Action, a git step on the way that fails (a checkout, the reset onto the base) is NOT DONE too. The base's own baseline is not the pull request's verdict: when it does not complete (a build broken on the base, a guard armed there), the log and the summary say it was the base, and the pull request is judged as 1.7.11 judged it — a pull request that fixes the base's broken build can pass.

**The signing key is never where the pull request's code runs (4b).** The workflow `agent-police ci` writes judges in a job with no signing key and uploads its report; a second workflow, `agent-police-sign.yml` (a `workflow_run` of the default branch, in the environment `agent-police-signing`), signs it without checking out or running the pull request's code. The judged tree is unchanged from 1.7.11 (the pull request merged into its base); the signer signs that commit only when it holds the pull request's head, the run succeeded, the run was the base's own `agent-police.yml`, and the pull request left that workflow alone. The Action blanks `AGENT_POLICE_SIGNING_KEY` and its passphrase; `attest sign` keeps both from the project's commands. `agent-police ci` tells the owner when an older workflow still holds the key. The README says exactly what the signature attests and what it does not. The signing run fetches the judged commit with the run's own read-only token (its checkout keeps no credentials, and a private repository refuses an unauthenticated fetch — every pull request there was signed NOT DONE). With `AGENT_POLICE_HUB` set, the judging job, which signs nothing, publishes the project's card with no signature — a signed verdict in its checkout came with the pull request, and a DONE signed for another commit was shown on a NOT DONE — and the signing run puts the verdict it signed on that card (`hub attest`), only on a card for the commit it signed, as 1.7.11's judging job showed its own.

**The README says what 1.7.11 does.** The Stop hook gives up after 3 rounds (not 5); `lessons` and `scan_complete` always run; level `basic` still runs the egress gate, the authority charter, the refusals and the hijack check; `selftest` proves each gate fires on its poisoned repo, not that it fires alone. The known limits are 1.7.11's, less what this release closed.

**The suite cleans up after itself.** `test/run-all.mjs` makes every temp dir, its own and every child's, under one private root and removes it when it exits — passed, failed or interrupted.

## 1.7.11 — scoped review round 4 (section 62)

**Closing 1.7 by the promise (section 63).** The README no longer says `judge accept` accepts text the hijack check flagged (1.7.7 took that away); it names `shield audit accept <file>`. The owner-side limits the four scoped rounds left open (approving a new dependency, `judge accept` against hub orders, `attest keygen` and CI, language, commands that do not exist here, committing `.agent-police/`, repeated messages) are listed under the threat model, one line each.

**Python projects get their tests run.** `install` / `init` find a Python project by `setup.py`, `setup.cfg`, `pytest.ini`, `tox.ini`, `conftest.py`, or only by its `tests/test_*.py` / `*_test.py` files, not only by `pyproject.toml` / `requirements.txt`. The command uses the Python this machine has: `python3` first, then `python`, then `py -3` on Windows. A test command that cannot start (exit 127 / 9009, "not found", no pytest) is ⚪ "the test command could not start", not "the tests fail", and a test claim is not marked FALSE because of it. A claim nothing here could check ("All tests pass" with no test command, "ESLint passes" with no lint gate) is listed under ⚪ Not checked in the handoff.

**Weak assertions are weak wherever they appear.** One shared check finds assertions that pass for almost any value: `notEqual` / `notStrictEqual` / `notDeep(Strict)Equal`, `expect(…).not.toBe`, `match(String(x), /\d+/)`, `equal(<predicate>, true)`; in Python, `in range(…)`, `in (a, b, c)`, `type(x) ==`, `(x > 0) == True`, `len(str(x))`. Replacing an exact assertion with one of these fails tests_not_weakened. A new test file whose only checks are of this kind fails no_weak_tests, and so do Python's bare `assert f(x)`, `!= v`, `< v` / `> v`. A new test that calls the code and asserts nothing, or only prints the result, is a test that checks nothing. A helper of the same file that asserts, `pytest.raises` and snapshot calls still count as checks.

**Expected values.** An expected value changed from a number to a formula (`Math.round(150 * 0.85)`, `round(150 * 0.85)`) or to a name (`expected`) is the expected value changed. A name assigned in the file is read as its number. A formula of plain numbers is worked out, so one that equals the old value is a refactor. With the code changed in the same diff it fails tests_not_weakened. With only the test changed it goes to review.

**Tests that leave the run.** The run count is compared with the base count plus the tests the change declares. A Python test defined twice in the same scope, and a test or assertion inside a bare string, fail tests_not_weakened. So do a mock / patch / monkeypatch / reassignment of the function the test asserts on (or of its module), and the tested names imported from a copy in the test tree instead of the source (review only when the source did not change).

**Unfinished work and missing values.** More stub notes count: "WIP", "coming soon", "follow-up PR", "to do:", "skeleton", "minimal version", "first pass", "not wired up yet", "not supported yet", "quick and dirty", and "later" / "simplified" when they are the note itself. A note that gives a reason or a ticket goes to review. A value the request names (`SAVE10`, `'VIP'`, `"pending"`) that appears nowhere in the change fails intent when the reply says it works, and goes to review otherwise.

**Dependencies from a URL.** `name @ git+…`, `-e git+…#egg=name` and an archive URL in requirements files are read as requirement names, so deps_declared and licenses see them.

**More claims.** "I updated README.md", "Added an entry to CHANGELOG.md", "עדכנתי את README.md" (said:file) are FALSE when that file has no change. "applyCoupon has a JSDoc comment" (said:doc) is FALSE when no doc comment was added. "ESLint passes", "the type check passes", "coverage is at 100%" (said:lint / typecheck / coverage) are CONFIRMED only by a configured gate that ran green. More test claims are read: "npm test ✅", "✅ Tests", "nothing fails", "CI should pass". A stated count the run contradicts ("5/5 tests pass" when 3 ran) is FALSE.

**Questions after a hand-over.** A question with no imperative ("why is the test failing?") is not folded into the open task as a new bug report. While nothing changes, the reply is judged by its claims; a change to the judge, a secret or an injected instruction still fails. The handoff keeps the request as not delivered, with what still fails. "ok thanks" or a question back does not answer an open question.

## 1.7.10 — scoped review round 3 (section 61)

**A hand-over stands on the full check.** When the Stop hook hands the agent over to the owner (the same failure again, or the last round), it runs the full check first if the round ran only the quick one, so a red suite, a false "All tests pass" and a known vulnerability are in the owner's report. A reply that claims the tests pass runs the suite in that round, whatever failed fast. Every gate the quick check skipped (no_known_vulns included) is listed under "Not checked", and the quick check's ledger says "deferred to the full check", not "to CI".

**A conversation after DONE is a conversation.** A stop that passes DONE is recorded on the task with the tree and commit it passed on. An ordinary follow-up in the same session ("great, thanks", "how would I run only that test?") marks the next turn as conversation. While nothing has changed, the reply is judged by its claims only, and the handoff keeps the request under ✅ Done.

**Tests that check only that the code exists.** When every added assertion in a test file only checks a type, that something is not None, that it is callable or has an attribute, or that it does not throw (`typeof … 'function'`, `doesNotThrow`, `instanceof`, `callable`, `is not None`, `isinstance`, `hasattr`), no_weak_tests fails with "checks only that X exists, not what it returns".

**Unfinished work without a TODO.** Comments that say "not yet implemented", "stubbed out", "mock implementation", "dummy value", "fake data until …" or "hack until …" are unfinished work. So is a new function whose body is empty or only `pass` / `...`; abstract methods, Protocol methods, `@overload`, `.pyi` / `.d.ts` files and functions named as no-ops are left alone. A name the request asks for that appears only in a comment is missing.

**Python weakening.** `… or True`, `==` changed to `!=`, `f(x) == f(x)`, an exact check loosened to `pytest.approx(…, abs=/rel=)`, and a bare `pytestmark = pytest.mark.skip` / `xfail` each fail tests_not_weakened. A pytest summary with only skipped or xfailed tests counts as 0 passed, so the fewer-tests check runs.

**An expected value replaced by the code's own result.** `discount(150), 135` ⇒ `discount(150), discount(150)` fails tests_not_weakened ("the expected value 135 was replaced by the code's own result"). A new self-compare with no deleted counterpart stays for review.

**More "tests pass" wordings are claims.** "1/1 green", "npm test is clean", "everything passes", "all checks are passing", "the test suite runs without errors" and "no failures".

**The agent's own test.** When the agent comments out an assertion in a test file it created in this task, the paste list says "restore the assertion you commented out (and fix the code it caught)" and ❌ Not done says so plainly. The owner is asked to confirm only for tests that existed before.

**Strict markdown check.** Markdown text that reads as injected is scored on every check, including the first strict one. It stays red, and the project stays halted, until the text is removed or accepted. Before, the next check called it clean and lifted its own halt. Markdown already committed at install is listed for review. The prompt hook compares flagged markdown with the markdown fingerprints.

**Not in this round:** findings 9–15 (shield and egress: xargs / find -exec / interpreter subprocess routes, curl short-flag clusters, more outside-read routes, in-place editors on instruction files, injection rules for more languages, key checks on WebFetch / WebSearch / MCP sends, and uploads of the project root). Their regression samples were not written in this pass.

## 1.7.9 — scoped review round 2 (section 60)

**Nothing changed is not done.** A request to make or change something, with no file changed and nothing committed since it came and no question open, fails intent: "nothing was changed for the request — the work was not done", whatever the reply says (an empty reply too). The owner's report never lists the request under ✅ Done when nothing changed for it, and while its questions wait it is under a new "⏳ Waiting for your answers" section.

**Half a request is not done.** Code the request names as work — `withTax(t)`, `total()`, `parse_price`, a backticked name — that appears nowhere in the change fails intent ("that part was not done"), and a reply sentence that says it added that name is FALSE under true_claims. "I upgraded / pinned X to V" is a claim now, checked against the manifests and lockfiles. "pytest passes", "the suite is green", "no failing tests" and "12 passed" are claims about the tests.

**The owner's decision stands on a full run.** The Stop hook no longer ends a turn as "the owner's decision" (a new dependency, its license) on the quick check alone: when the suite was skipped, it runs first, so a red suite blocks and is named.

**Rewritten tests are seen.** An assertion replaced by one on the same function with another input and another expected value fails tests_not_weakened when the code under test changed in the same diff (for review otherwise). A row taken out of or changed in a `pytest.mark.parametrize` or `test.each` table, and a saved snapshot (`__snapshots__/*.snap`, `*.snapshot`, `*.ambr`) that now expects a different output, are changed expected values — unless the customer gave the new values or asked for the snapshot update.

**Unfinished work in any words.** A TODO / FIXME that says implement, later, stub, placeholder, for now, temporary, real logic or not yet is unfinished work whatever its length, and so is such a comment beside a `return` / `pass`; a TODO that gives its reason (because, blocked by, see #123) stays for review. In a new test file, an assertion written as a comment and a test whose body is empty, only a comment or TODO, or only `pass` / `...` are caught (tests_not_weakened / no_weak_tests).

**The owner's own work is not the request's.** A task records the working tree when the request comes; intent and the scope of the work are measured from there (the weakening gates keep the base commit), and the report names what was "present before this request".

**Plain words.** Every gate the verdict can name has an English and a Hebrew label in the owner's report and the paste list (reports_gaps, lock_consistent, no_debug_left …) — kept by a test.

**Wrappers.** `X=$(cat .env); …` and `env > file` are no longer read as a VAR= prefix or an `env` wrapper, so the guards see the command that runs.

**Install.** A non-vendored install from a checkout writes every agent hook as `node "<this copy's absolute path>"` and says the path is machine-local, instead of `npx agent-police` (not on npm — the hooks failed open). The README quick start and the Claude Code plugin skill install from a checkout with `--vendor`, and the plugin line uses `/plugin marketplace add`.

**Not in this round:** secret variables in a request's body or headers, a glob of `.env` in a read or a send, and the environment written to a file then uploaded (findings 11–13); the rest of finding 10 (judging both the raw and the unwrapped command, the held text built from the raw command).

## 1.7.8 — scoped review round 1, the verdict side (section 59)

**A red suite is red, whatever the exit code.** verify reads the failure count the test runner itself prints (node, jest, vitest, mocha, pytest, unittest, cargo, go): a test command that exits 0 while its summary names a failed test is ❌, and the report says "the test command exited 0, but N test(s) failed". A `"test"` script that can no longer fail (`|| true`, `|| exit 0`, `--passWithNoTests`), or that now filters tests out (`--test-only`, `-k`, `--grep` …), and a `conftest.py` that forces the exit status, weaken the tests; any other change to the test script is for review.

**Tests left out through the runner's config are seen.** A pytest `addopts` that adds `-k`, `--deselect`, `--ignore` or `-m "not …"` (pytest.ini, setup.cfg, tox.ini, pyproject), a conftest collection hook that drops tests, and a jest / vitest / mocha ignore or exclude fail tests_not_weakened. When fewer tests ran than at the task's base and none was knowingly removed, it says "N fewer tests ran" (the base count is measured once per base and kept sealed).

**Switched-off tests are recognised in more forms.** An assertion turned into a comment is matched by its text, so commenting one out beside a new or copied one no longer balances the count. node:test's `{ skip: … }` / `{ todo: … }` and `t.todo`, `return; // reason`, an assertion under a new `process.env` / `os.environ` guard, a try/catch over several lines that drops the failure, Python's `if False:`, `return  # reason`, `except AssertionError` and `assert True` are each flagged. `test.only` / `fit` / `fdescribe` are named as "only this test runs now".

**Python asserts are judged like JS ones.** `assert x == v` is strong; a bare `assert x`, `is not None`, `isinstance`, `< n` and `abs(…) < n` are weak; a changed expected value in `assert … == v` is flagged unless the customer gave it. `typeof x === 'number'` is weak in JS too.

**New Python dependencies count.** requirements files, PEP 621 arrays, Poetry tables, Pipfile and setup.py / setup.cfg give their names to deps_declared, so lock_consistent names a stale poetry.lock / uv.lock / pdm.lock / Pipfile.lock. A new dependency whose license cannot be read on the machine makes licenses ⚪ with that reason, never ✅.

**The hooks.** A message in a new session starts that session's own task; another session's request, base and open questions no longer judge it. When the Stop hook lets the agent end without DONE (give-up, the same failure again, the owner's decision, OSV not answering), Claude Code users see the message: it is sent as `systemMessage` on stdout. In round 1, when the reply says the tests pass and only the reply or the task failed the quick check, the full suite runs in the same round.

**The report.** A committed key is named by file, line and kind — its value is no longer printed into the conversation, handoff.md or the verdict cache. true_claims is printed once. The paste list carries the concrete intent reason.

**Not in this round** (still open from the same review): the hijack-side findings — download-and-run commands, scripts the agent writes that send secrets, interpreter heredocs, project archives, gh / cloud upload routes, pulled commits and new remotes, the injection scorer's false alarms and misses, secrets files read through other tools, MCP servers added through the agents' CLIs, instruction files named by a bare basename or written through other routes — and the hub's orders that need hub.url.

## 1.7.7 — the threat model, and 17 fixes checked against it (sections 55–58)

**The promise is written down.** The README (English and Hebrew, dev and public) and the closing report say what the police catches on the machine — an honest agent that makes mistakes or cuts corners, an agent hijacked by text it reads (also through `env`, `timeout`, `nice`, `bash -c`, `git -C`, a temp copy then an upload, or a small script it was told to write), and accidents (a secret about to leave, a secrets file read into the conversation) — and what it does not: an agent deliberately engineering against the police's own code. That is covered outside the machine: the CI check on every PR (`agent-police ci`), branch protection requiring `agent-police / verdict`, and signed orders. The FAQ "can the agent trick it?" points there.

**The verdict always runs.** An open question no longer ends the Stop hook early: the work is judged with `--waiting`, so the open question itself is not a failure, and any other failing gate blocks with a line saying the questions stay open. An assertion turned into a comment (`// assert…`, `# assert…`, or a `/* … */` around it) is a weakened test. `no_known_vulns` asks about what will really install — a `package.json` pin the lockfile does not match, a `go.mod` replace — and shows ⚪ "not checked" for a range a stale lockfile does not satisfy, a local replace, and a dependency from a URL or a repository (any password in the URL is removed). A secrets file copied under another name (`cp`, a redirect, `tee`, `tar` / `zip`, `dd`) is still the secret, in that command and in the session's later ones. The send, decoy, outside-read, secret-read and egress guards judge the command with its everyday wrappers taken off.

**More hijacks are caught.** A plain order to send the environment, an env file or a secrets file somewhere scores as an injection, and so do "ignore the earlier rules" / "send the keys" in Arabic, Russian, French, Spanish, German and Chinese, and code piped from the internet into a shell when said in prose or tied to the agent's turn — a README's install block, a security policy and prohibitions in every language stay under the line. `CLAUDE.md` imports from outside the project are read by the hijack check and a write to them is held. `.cursor/commands/` is an instruction file. `judge accept` never accepts injected text or hidden characters and names the one command that accepts that exact text; once the text is gone, a clean check lifts the halt it made. At strict, the owner's own commits between the turns are not held as a pull. At a halt the agent gets one instruction.

**What the owner is told works.** Owner commands are only `npx agent-police …` or `node .agent-police/bin/agent-police.mjs …` — never a path in the npx cache — in what is printed, the sealed records, the ping, the hub summary and the hub's buttons. A project halted over injected text leads in the hub with "look at the file first". `hub serve` with a wrong or missing passphrase says so and how to give it, instead of "run attest keygen". A protect order refused for an untrusted signer runs once the owner trusts that signer. Hebrew owner surfaces are in Hebrew.

**Known false alarm:** a `curl … | bash` install line written in plain prose, with no code formatting, now counts as an injection.

## 1.7.6 — review round 7 (13 findings, each with its own test, section 54)

**A FIFO cannot hang the police.** Every read the police makes of a path opens it without waiting and refuses what is not a regular file, and a write into `.harness/` replaces a FIFO there (`lib/fsafe.mjs`): a FIFO put at the decoy, at a pending `@import` of `CLAUDE.md` or among the records no longer makes each hook time out — and a timed-out hook blocked nothing, so the send hold, the instruction-file guard, the halt and the verdict had all been skipped. The shell routes to `.harness/.env` (and `mkfifo` / `mknod` into `.harness/`) are refused, as Write to it already was.

**The decoy is only ever the one the police planted.** A decoy that is not a regular file, or not of the planted shape (`sk-proj-` and 40 characters), is a red hijack-check finding (a halt at strict) and is planted anew; it is never read as it is or matched against. A short value no longer makes every command — even `ls` — "carry the decoy".

**The hub's commands go where they say.** A button on a hub page opened as a file copies this project's own command (the vendored copy or `npx`) with the hub's real place (`hub build` records the clone's origin or its absolute path, never `.`), and says it signs with your key when you run it. `hub order` refuses a project as its hub instead of committing the order into it and calling it sent. A protect order that lowers what the project last reported says at send time — in the reader's language — that it waits for `approve <code>` in the agent's chat (the CLI line and `hub serve`'s).

**The owner's word, read as meant.** A refusal in the chat is a refusal: "Do not approve <code>", "never approve", "לא מאשר", "deny <code>" and "אל תאשר" record a denial (a waiting order is refused), and the police's own wording pasted back ("write "approve …" in this chat", "they approve by replying: approve …") approves nothing. The hub's `resume` order lifts a hijack-check halt the way a local `resume` does, so the next turn does not halt again for the same text. An owner who removes entries from `vulns_ok`, `universal_off`, `licenses_ok` or `scan_skip_ok` (or adds a `default_scope`) tightens the judge: no code is asked and `harness_intact` stays ✅.

**The owner-command guard reads the resolved script path.** `.agent-police//lib/judge.mjs`, `lib/./judge.mjs`, `cd .agent-police/lib && node judge.mjs`, a glob, `set -- judge accept; … "$@"`, `npx agent-police@<version>` and `npm exec agent-police --` are all the owner command they run, and refused.

**More roads out are held at strict, and say why.** bash's `/dev/tcp` and `/dev/udp`, cloud copies (`aws s3`, `gsutil`, `gcloud storage`, `az storage`, `azcopy`, `rclone`), registry pushes, DNS lookups (and one carrying `$(…)` is a send), mail, `openssl s_client`, and perl / php / ruby / PowerShell network code; one that names the decoy halts the project. A send held at strict with nothing read from outside says the level is why, not "what was read". A moderate vulnerability with no fix names the two choices and says the gate does not block on it. The README and the closing report name this version.

## 1.7.5 — the fifth review round (21 findings, each with its own test, section 53)

**The owner-command and commit guards read the command the way the shell builds it.** A quoted subcommand (`'judge' accept`), a quote-split path (`"harness"".json"`) or a backslash escape (`re\sume`) no longer hides from them: `dequote` joins a word's pieces and drops the quotes and escapes, blanking only the text a command prints (`echo` / `printf`, heredoc bodies). A police command smuggled through `$(…)`, backticks, `eval`, a pipe into a shell, `xargs` or a `git -c alias.*=!…` is refused, since that form hides which subcommand runs. The pre-tool hook fires on **every** tool (matcher `*`), and a tool that runs a command under another name (Monitor, the Windows PowerShell / terminal tools) is a Bash call for every guard.

**Every file agents follow is guarded and checked, and the guard is bounded.** `.claude/rules/`, `.claude/output-styles/`, `AGENTS.override.md`, `.gemini/`, `.vscode/mcp.json`, `.github/agents/`, `.github/chatmodes/`, `QWEN.md`, `.agents/`, `.opencode/`, `.trae/rules/`, `.windsurf/workflows/` now count. ## 1.7 — closing the product

**Protection level, and how often the hijack check runs — chosen at install and from the control room:**

Unsigned, foreign-signed, expired, replayed or invalid orders are refused, and so is one that would overwrite changes to `harness.json` nobody committed. The owner's change is not counted as tampering by the agent.
- The agent cannot change the level: the hooks read the committed `harness.json`, and `hub order` / `hub serve` are now refused when the agent runs them (like `install`), since they sign with the owner's key.

**A periodic hijack check** (`agent-police shield audit`). The shield guards each call; this looks back for what slipped past it or came another way.
- **On the owner's schedule, with no cron.** `"protection": { "audit": { "every": "daily" | "weekly" | "monthly" | "off" } }` (weekly by default; the old `"protection": "<level>"` still works). It runs at the start of an agent turn when due, by the committed `harness.json`, in milliseconds, and never holds the turn on its own failure. `--if-due` for CI, `show` for the last result.
- **What it checks.** The files AI agents follow, with the shield's own list and injection measure: injected-looking text is red; a change since the last check that did not come through the owner (an approval code, a request that named the file, the owner's own edit) is for review. The decoy: gone, changed or seen leaving is red. What came in from outside since the last check. an external injection guard's audit chain, verified by that guard itself when `HIJACK_COP_AUDIT` is set (not installed is ⚪, never red). At level `strict`, every markdown file added or changed since the last check.

**Old knowledge: a new dependency with a known vulnerability** (`no_known_vulns`).
- **What it asks.** Every exact version that is new or upgraded — `package-lock.json`, transitive ones too, and pinned Python requirements — goes to OSV in one batch question (6 s in all; answers kept 24 hours in `.harness/osv-cache.json`, which the agent may not write; `AP_OSV_URL` points it elsewhere).

- **Never a false green.** OSV not answering is ⚪ with the reason, never green, and is not cached; the quick check stays offline and leaves it to the full check.
- **Who ends it.** When the only thing left is a vulnerability with no fix yet, it is the owner's decision and the agent ends — one with a fix is the agent's to upgrade. `agent-police selftest` proves it against a local stand-in for OSV.

## 1.1

- **Four agents, one police:** Claude Code, Cursor, Codex and GitHub Copilot (CLI and cloud agent) — the request becomes the task contract, a stop hook sends the agent back until DONE, the judge's files cannot be read. Installed by the same one command.
- **Scope with no configuration:** when the request names its files, a change to any other file is caught.
- **The digest:** what the police caught, in plain words, to your phone (Telegram or a webhook) and as a dashboard; a stuck agent pings you.
- **GitLab** merge requests get the same trusted judge. **Windows:** CRLF checkouts no longer read as tampering; hooks run in PowerShell.
- **The same mistake never twice:** `lesson add` turns a fixed mistake into an enforced rule (a forbidden pattern or a regression test). Lessons only accumulate; removing or weakening one is caught, and its mistake is still enforced. Unsafe patterns (ReDoS) are refused.
- **Stuck loops stop:** the same failure again after the way out ⇒ the agent stops and asks you, instead of retrying the same fix.
- **Nothing passes silently:** changed files the checks cannot read (submodules, symlinks, LFS pointers, binaries) are named and fail the verdict.
- **A judge that can be trusted:** `ci` writes a GitHub workflow that judges every pull request with the engine and config from the base branch; a hand-edited engine copy is caught.
- **verify shows the test count**, and warns when a sub-package's tests may not be reached. Updating agent-police is committable; re-installing changes nothing.

## 1.0

- **Live guard** for any coding agent: instructions (AGENTS.md, CLAUDE.md, Cursor, Copilot, Gemini), git hooks, and Claude Code hooks.
- **Catches:** deleted / skipped / weakened tests, stubs, swallowed errors, secrets and personal data in code, a red suite at "done", code changed with no test that proves it.
- **Asks instead of guessing:** a number or rule nobody gave becomes a question, collected at the end.
- **Flaky tests:** a failing test is re-run and compared with the code before the change; an already-flaky test is flagged, not blamed.
- **`prove`:** judge finished work the guard never saw: honest · gamed · failed, with a one-page proof.
- **Plain report:** done · not done and why · what I need from you, plus a ready-to-paste fix list.
- **Runs locally and offline**, installed into the project; Claude Code one-click plugin.
